# Variance check - SAP side (EDS, client 900, transport EDSK9B0ER0 "MM_41/7122_Costing Cockpit PO variance check_SA_27.11")

Automates the daily routine on **ZMM_PCOST** (`ZMM_MB31_MATERIAL_COST_PERPC`) + **ZMM_COST** (`ZAUFM_UTILITY_DETAILS2VNEW`): find the process orders whose cost per piece is
more than 4 % away from standard, then the components whose rate caused it. Read-only (no write, no COMMIT). Screen: Costing Cockpit side pane > Variance check.

| Object | What |
|---|---|
| `ZPOVAR_S_ROW` | row structure (`zpovar_s_row.ddls.txt`) - active on EDS |
| `ZCL_MM_PO_VARIANCE` | `orders( )` = ZMM_PCOST, `components( aufnr )` = ZMM_COST (`zcl_mm_po_variance.abap`) - active on EDS |
| MPC_EXT `povar_define` | entity `PoVar` / set `PoVarSet` (`mpc_povar_define.abap`, generated by `gen_povar.py` from the structure); `lc_model_ts` bumped to 20261127120000 |
| DPC_EXT branch | `dpc_povar_branch.abap`, before `ls_par = wac_par(` in `get_entityset`; `'PoVarSet'` added to the "other sets" exclusion |

## Orders (default grain) = ZMM_PCOST
- Filter: `Werks`, `Matnr`, `Aufnr`, `PostType` (default `01` process orders), `DateFrom`/`DateTo`, `DateType` (`C` = record created **or** changed on = ZMM_PCOST "Date" field, default; `P` = `BUDAT_MKPF`). At least a plant, material or order.
- Per ZMB31_POUTILITY row: total = machine + labour + power + steam + PM + RM + perfume + other + conversion + |consumer scheme| + |trade scheme| (the report's own sum and ABS); `ActPc` = total / MENGE.
- Standard: MCHA (matnr, werks, charg) -> BWTAR -> MBEW (matnr, bwkey = werks, bwtar): `STPRS` when VPRSV = S, `VERPR` when V. `DiffPct` = (std - actual) / std x 100 (report formula and sign: negative = costlier).
- Differences to the report, on purpose: price divided by PEINH (the report ignores it; same result for PEINH 1); a batch without MCHA record is valued with BWTAR blank instead of no price;
  ZMM_PCOST's `p_per` keeps only `diff_per >= p_per` (cheaper side only) - the app filters by the absolute value with a direction switch. The report's budget columns
  (COST_PC / ACOST_PC) are never filled in the report (`lt_mara` is empty), so they are not carried.
- Plant authorisation `ZCL_MM_BOM_COST_AUTH=>check_plant`; at most 5,000 receipts per call (PARTIAL message).

## Breakup (`Aufnr eq '<one order>' and Grain eq 'C'`) = ZMM_COST
- `ZCL_AUFM_UTILITY3=>get_mat_consumption_details( FERT, order, 31.12.9999, abnormal 'X' )` - the parameters ZMM_PCOST passes when it drills down to ZMM_COST.
- Rows: `H` level 0 (finished-good receipt, `FgQty`), `W` WIP lines (their components come at the next level), `C` consumed components.
- Component standard: its OWN batch valuation type (MCHA of matnr / werks / charg), not the drill row's BWTAR (the utility fills that from the parent batch). Same S/V rule, / PEINH.
- `VarVal` = actual value (DMBTR) - standard rate x actual quantity; `VarFgPc` = VarVal / FG quantity. Flag `UOM` when the consumed unit differs from MARA-MEINS.

## CK13N (added at the user's request: "connect with CK13N, MBEW variance also required")
- Order rows (O) and the finished-good row (H) also carry `CkPc` = CK13N current standard estimate per base unit (`ZCL_MM_CK_READER->pick`, the Standard cost screen's default:
  latest released estimate valid in the last CK_WINDOW_DAYS, else the newest), with `CkKadky`, `CkKlvar`, `CkStatus`, `CkDiffPct` (same sign as Diff %) and `CkVarVal` = (actual - CK13N) x qty.
- Components against CK13N are compared in the APP, not in SAP: the CK13N costing structure (every level, released values, lib/ck/structure.ts, verified against CK13N on 26.11)
  x pieces produced, split into rate variance (actual value - CK13N rate x actual qty) and quantity variance ((actual - CK13N qty) x CK13N rate). MBEW stays as the second view.
